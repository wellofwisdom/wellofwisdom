# Good first issues

Twenty scoped tasks, ready to paste into GitHub as issues. Each file is one
issue: a title, the labels, the file paths to touch, the steps, and the checks
that prove it works.

How to use them:

1. Create the label `good first issue` on the repo if it does not exist.
2. Open a file below, copy its body into a new issue, and add the labels named
   in the `Labels:` line.
3. Keep the checkboxes: a contributor can see when they are done.

Sizes are honest. `Small` is an evening for someone new to the repo. `Medium` is
a weekend.

A note on overlap. Several branches are open right now (frontend lint and tests,
server integration tests, the website pages, the speech input work). If a file in
your issue is being changed on a branch, say so on the issue and rebase before you
start. The issue text names the files, so a conflict is easy to spot early.
