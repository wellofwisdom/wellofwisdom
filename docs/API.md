# HTTP API

Every route the server answers, grouped by router. Generated by reading
`server/routes/*.js` and `server/index.js` on 14 September 2026, so it matches
what the code does today, not what it was meant to do.

Agents and scripts are welcome to read this file. `README.md` links to it, and
the public routes below need no session at all.

## Ground rules

**Base URL.** Same origin as the app. In development that is
`http://localhost:3000`.

**Sessions.** A login sets an HttpOnly cookie named `wow_session`, valid for 30
days, `SameSite=Lax`, and `Secure` when `COOKIE_SECURE=true`. Send it on every
request.

**API tokens.** A guide creates a token in Settings (API tokens card). It looks
like `wow_` plus 32 random bytes in base64url, is shown once, and is stored only
as a SHA-256 hash. Send it as `Authorization: Bearer wow_...`. It acts as that
guide limited to its scopes (`read`, `courses:write`, `learners:read`,
`progress:read`). An unknown or revoked token gets 401. Bearer requests are
rate limited per token (120 per minute) and skip cookie checks. Learners cannot
create tokens. See also `docs/MCP.md` and `POST /api/tokens` below.

**Body format.** JSON for everything under `/api`, except `POST /api/uploads`,
which takes the raw file as the body. Big pastes and course packages get a
larger parser: `/api/courses/import`, `/api/courses/worksheet-import`,
`/api/courses/worksheet-ocr` and `/api/community/import` accept up to 25 MB
(`IMPORT_BODY_LIMIT`). Everything else is capped at 2 MB. Video and audio
uploads are capped separately by `UPLOAD_MAX_VIDEO_MB`, 500 MB by default.

**Errors.** A failed request answers with a JSON object holding an `error` code,
for example `{ "error": "not_found" }`. A code means the same thing everywhere.
An unknown path under `/api` answers `404 { "error": "not_found" }`. A server
fault answers `500 { "error": "internal", "requestId": "..." }`, and the same id
is in the `x-request-id` response header, so a self-hoster can quote one line.
Common codes: `auth_required` (401), `parent_only` and `not_allowed` (403),
`not_found` (404), `too_many_attempts` (429), `ai_not_configured` and
`db_required` (503).

**Rate limits.** Per client IP, in memory, so a restart clears them.
`POST /api/auth/login` and `POST /api/auth/learner-login` allow 10 attempts per
15 minutes. `POST /api/auth/signup` and `POST /api/auth/join` allow 15 per 15
minutes while the invite gate is on. `POST /api/auth/google` allows 20 per 10
minutes. `POST /api/demo/login` and `POST /api/demo/upgrade` allow 20 per 10
minutes. `/api/public` allows 120 requests per minute. `POST /api/waitlist`
allows one per 30 seconds per IP and email.

**Which IP counts.** `TRUST_PROXY` decides how many proxy hops to trust, default
1. Behind Cloudflare set `CLIENT_IP_HEADER=cf-connecting-ip`. Get this wrong on
a public instance and the login limiter keys on a spoofable address.

## Who can call what

A signed-in grown-up carries a guide role. A learner is a different kind of
user entirely: a learner reaches `/api/learn`, `/api/worlds`, `/api/tutor` and
`/api/me`, and nothing else.

| Role | Rank | In one line |
|---|---|---|
| `owner` | 4 | Everything, including invites and deleting the family. |
| `guide` | 3 | Teaches everyone: courses, plans, grading, learner profiles. |
| `assistant` | 2 | Teaches only the learners assigned to them. A tutor. |
| `observer` | 1 | Sees progress and reports. Changes nothing. |

Three middlewares do the work:

- `auth.authRequired` needs a session, any role.
- `auth.parentOnly` needs a grown-up session. Any of the four roles passes.
- `auth.requirePerm("action")` needs one of the roles listed for that action in
  `server/lib/perm.js`. An unknown action denies, so a typo fails closed.
- `auth.denyReadOnly` runs once, app wide on `/api`. An observer gets a `GET`
  and nothing else, whatever a route forgot to check.
- `preview.attachPreview` runs on `/api/me`, `/api/learn`, `/api/worlds` and
  `/api/tutor`. A guide adds `?as=<learnerId>` or the `x-preview-learner`
  header to read as that learner. `preview.denyPreviewWrites` then refuses every
  write during a preview, so "view as learner" can never change anything.

| Action | owner | guide | assistant | observer |
|---|---|---|---|---|
| `manage_guides`, `manage_family`, `delete_family`, `manage_billing` | yes | | | |
| `create_course`, `edit_course`, `grade` | yes | yes | yes | |
| `build_world`, `record_attendance`, `record_assessment`, `spend_ai` | yes | yes | yes | |
| `delete_course`, `publish_course`, `share_course` | yes | yes | | |
| `create_learner`, `edit_learner`, `set_compliance` | yes | yes | | |
| `grant_reward`, `set_tutor_mode`, `spend_media` | yes | yes | | |
| `delete_learner` | yes | | | |
| `view_progress`, `view_reports`, `view_courses` | yes | yes | yes | yes |
| `view_tutor_log` | yes | yes | | yes |

## Routes outside `/api`

These are mounted at the app root, so the `/api` guards and the JSON parser do
not apply to them.

### GET /media/:id
Auth: read in the handler. A public upload is open to anyone. Anything else
needs a session in the owning family.
Returns: the stored file, with `Content-Type` from its mime, `Accept-Ranges:
bytes`, a `206` and `Content-Range` on a range request, and
`Content-Disposition: attachment` when `?download` is set.
Notes: this is what an `<audio>`, `<video>` or `<img>` tag points at.

### GET /media/:id/captions.vtt
Auth: same rule as `GET /media/:id`
Returns: the caption track as `text/vtt; charset=utf-8`, cached for 5 minutes,
or `404 { "error": "no_captions" }` when no track is ready.

### GET /robots.txt, GET /sitemap.xml, GET /llms.txt
Auth: none. Discovery files for crawlers and for AI tools.

### GET /c/:slug and GET /c/:slug.txt
Auth: none. The first is the share page for a published course, served with real
head tags so a link unfurler sees a title. The second is the same course as plain
text with answer keys stripped, cross-origin readable, built for research tools.

### Everything else
Auth: none. Any other path serves the app shell, which then routes on the client
side.

## Auth (/api/auth)
Mounted in `server/index.js`. No router level guard; each route below states its own check. `auth.denyReadOnly` also runs app wide on /api and blocks non GET requests from an observer.

### GET /api/auth/config
Auth: none
Body: none
Returns: `{ inviteRequired, googleEnabled, googleClientId }`
Notes: Public config for the signup form. Tells the page whether an invite code is needed.

### POST /api/auth/signup
Auth: none. Rate limited per IP only while the invite gate is on (15 attempts per 15 minutes).
Body: `familyName`, `name`, `email`, `password`, optional `inviteCode`
Returns: `{ ok: true }`, sets the `wow_session` cookie
Notes: Creates a new family with the caller as parent owner. Password must be 8 characters or more. `inviteCode` is required when the server is invite gated.

### POST /api/auth/join
Auth: none, rate limited per IP (15 attempts per 15 minutes). The invite token is the credential.
Body: `token`, `name`, `email`, `password`
Returns: `{ ok: true, role }`, sets the `wow_session` cookie
Notes: Joins an existing family as a second grown-up. The invite is claimed once, so two people cannot use the same link. An assistant arrives already scoped to the learners on the invite.

### POST /api/auth/login
Auth: none, rate limited per IP (10 attempts per 15 minutes)
Body: `email`, `password`
Returns: `{ ok: true }`, sets the `wow_session` cookie
Notes: Parent sign in.

### POST /api/auth/learner-login
Auth: none, rate limited per IP (10 attempts per 15 minutes)
Body: `joinCode`, `username`, `pin`
Returns: `{ ok: true }`, sets the `wow_session` cookie
Notes: Signs in a learner by family join code and username.

### POST /api/auth/google
Auth: none, rate limited per IP (20 attempts per 10 minutes)
Body: `credential`, optional `familyName`, optional `inviteCode`
Returns: `{ ok: true, mode }`, where `mode` is `"login"` or `"signup"`. Sets the `wow_session` cookie.
Notes: Signs in, or creates a family on the first Google sign in. The invite gate applies to new families only. Returns 503 `google_not_configured` when Google is not set up.

### POST /api/auth/logout
Auth: none
Body: none
Returns: `{ ok: true }`, clears the `wow_session` cookie
Notes: Safe to call while logged out.

## Family (/api/family)
Mounted in `server/index.js`. Router level guard: `router.use(auth.parentOnly)`. Every query is scoped to `req.user.familyId`. `auth.denyReadOnly` also runs app wide on /api.

### GET /api/family/learners
Auth: `auth.parentOnly`
Body: none
Returns: `{ learners }`
Notes: An assistant sees only their assigned learners. Owner, guide and observer see everyone.

### POST /api/family/learners
Auth: `auth.parentOnly`, then `auth.requirePerm("create_learner")`
Body: `name`, `username`, `pin`, optional `gradeLevel`, `interests`, `readingLevel`, `aiNotes`, `email`
Returns: `{ learner }` with status 201
Notes: Username is 2 to 24 characters, lowercase letters, digits, `_`, `.` or `-`. PIN is 4 to 6 digits. A name already used in the family returns 409 `username_taken`.

### PATCH /api/family/learners/:id
Auth: `auth.parentOnly`, then `auth.requirePerm("edit_learner")`
Body: any of `name`, `pin`, `gradeLevel`, `interests`, `readingLevel`, `aiNotes`, `email`
Returns: `{ learner }`
Notes: Only the fields sent are changed. An empty body returns `nothing_to_update`. Another family's learner gives 404.

### DELETE /api/family/learners/:id
Auth: `auth.parentOnly`, then `auth.requirePerm("delete_learner")`
Body: none
Returns: `{ ok: true }`
Notes: Only a learner in the caller family is deleted.

### GET /api/family
Auth: `auth.parentOnly`
Body: none
Returns: `{ family }` with `id`, `name`, `join_code`, `created_at`
Notes: The join code a learner types at login, shown in Settings.

## Learn (/api/learn)

Mounted in `server/index.js`. Every route requires a session (`router.use(auth.authRequired)`), and the learner is taken from the session rather than from the body.

Two app wide middlewares also apply. `preview.attachPreview` runs on this mount, so a guide may add `?as=<learnerId>` or the `x-preview-learner` header and read as that learner. `preview.denyPreviewWrites` then refuses every write during a preview with 403 `{ error: "preview_read_only" }`. Separately, `auth.denyReadOnly` runs app wide on `/api`, so an observer cannot send a non GET here.

Every learner route is scoped to the caller's family, only published courses, and a course the learner owns or one meant for the whole family. Another family's rows are never returned.

### GET /api/learn/courses

Auth: any signed-in user, learner identity comes from the session
Body: none
Returns: `{ courses }`. Each course has `id`, `title`, `topic`, `lens`, `description`, `lesson_count`, `lessons_done`.
Notes: only courses assigned to this learner or to the whole family come back.

### GET /api/learn/courses/:id

Auth: any signed-in user, learner identity comes from the session

## Tokens (/api/tokens)

Mounted at `/api/tokens`. Every route needs a session (`auth.authRequired`). A
learner is refused with 403 `parent_only`. Each token belongs to the guide who
created it, in that guide's family. Bearer auth on other routes uses these
tokens; this router is how they are managed.

### GET /api/tokens
Auth: `auth.authRequired`, then a parent check
Returns: `{ tokens }`. Each token has `id`, `name`, `scopes`, `lastUsedAt`, `createdAt`, `revokedAt`
Notes: never returns the raw token or its hash. Family and user scoped.

### POST /api/tokens
Auth: `auth.authRequired`, then a parent check
Body: `name`, `scopes` (array of `read`, `courses:write`, `learners:read`, `progress:read`)
Returns: 201 `{ token, id, name, scopes, createdAt }`. `token` is `wow_...` and is shown once
Notes: 400 `name_required`, `name_too_long`, `scopes_required`.

### DELETE /api/tokens/:id
Auth: `auth.authRequired`, then a parent check
Returns: `{ ok: true }`
Notes: revokes the token. Unknown or not yours gives 404 `not_found`. A revoked token answers 401 on bearer use.

Bearer use elsewhere: send `Authorization: Bearer wow_...`. On any route it is
checked before the cookie. Unknown or revoked is 401, insufficient scope is
403, and per-token rate limit is 120 per minute (429 `too_many_attempts`).

## Instance admin

Instance-wide settings are guarded by `requireInstanceAdmin` from `server/lib/instanceAdmin.js`, not by family permissions.

- `GET /api/ai/config` and `PUT /api/ai/config`
- `GET /api/ai/limits` and `PUT /api/ai/limits`
- `GET /api/stt/config` and `PUT /api/stt/config`
- `GET /api/mail/config` and `PUT /api/mail/config` (provider)
- `GET /api/media/config` and `PUT /api/media/config`

Who is the admin: never a learner, never anyone but a family owner, never a
demo family. With `INSTANCE_ADMIN_EMAILS` set, only owners whose email is on
that list. Without it, the owners of the first real family on the server.
